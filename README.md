## 🦢 Что это

**КАИСТ** - веб-приложение с расписанием для студентов КНИТУ-КАИ. Открывается в браузере, ставится на домашний экран как обычное приложение и дальше работает как нативное.

Никаких регистраций, аккаунтов и подписок. Открыл - сразу видишь свои пары.

### 📚 Что внутри

- **Расписание** - пары по дням и неделям, с аудиториями, корпусами и типами занятий.
- **Избранные группы** - можно добавить несколько групп и переключаться между ними в один тап.
- **Преподаватели** - кто и что ведёт у твоей группы.
- **Одногруппники** - список группы со старостой.
- **Экзамены** - чтобы не искать их по вузовским сайтам.
- **Потоки** - в карточке пары видно, с какими группами вы сидите вместе.

### ✨ Почему это удобно

- **Работает офлайн.** Расписание скачивается один раз и хранится на устройстве. В метро, в лифте, на паре со слабым Wi-Fi - всё открывается мгновенно. Обновления подтягиваются сами, когда сеть появляется.
- **Всегда свежая версия.** При запуске приложение само проверяет обновления и, если нужно, тихо обновляется, прежде чем показать расписание. Никаких «обновите страницу» и застрявших старых версий.
- **Простой интерфейс.** Никаких перегруженных меню. Светлая и тёмная темы переключаются в один тап или подстраиваются под систему.
- **Устанавливается на телефон.** На iOS - через «Поделиться» → «На экран Домой». На Android - через меню браузера → «Установить приложение». Дальше открывается как обычное приложение.

### 🚀 Как начать

1. Открой приложение.
2. Установи на устройство (по желанию, но так удобнее).
3. Введи номер группы - приложение подскажет подходящие.
4. Готово. Расписание уже на устройстве.

### 🆘 Если что-то пошло не так

Если приложение зависло на старой версии или странно себя ведёт, можно принудительно сбросить кэш через ссылку:

- **`https://kaist.pro/?reset=cache`** - сбросит только кэш файлов (Service Worker). Группы и настройки сохранятся.
- **`https://kaist.pro/?reset=all`** - полный сброс: кэш, группы, тема, расписание. Сохранится только анонимный ID устройства для статистики.

Эти ссылки можно использовать, чтобы починить «залипшую» версию без переустановки приложения.


## 🛠 Технические детали

> Для тех, кому интересно, как это устроено.

### 🏗 Как это работает

**КАИСТ** устроен по принципу **offline-first**: все данные, которые видит пользователь (расписание, экзамены, студенты, реклама), хранятся прямо в браузере - в IndexedDB. При старте приложение отдаёт закэшированное сразу, а в фоне, если есть сеть, подтягивает обновления. В метро, в лифте, на паре со слабым Wi-Fi всё открывается мгновенно, потому что сеть для отображения не нужна.

Сами данные раздаёт отдельный сервис — клиент лишь скачивает их и складывает к себе. Никаких аккаунтов и пользовательских данных: всё, что нужно приложению, — это номер группы.

Такая схема даёт три вещи:

- 💰 **Ноль затрат на инфраструктуру со стороны клиента** - статика SPA + тонкий источник данных.
- ⚡ **Максимальная скорость** - качаем только то, что изменилось.
- 📡 **Офлайн по умолчанию** - все данные лежат в IndexedDB, сеть нужна только для обновлений.

### 🔄 Как работают обновления

Обновления — самая сложная часть PWA. На iOS Service Worker умеет «залипать» на старой версии, и стандартный баннер «Доступно обновление» там часто просто не срабатывает. Поэтому в КАИСТ реализована **гибридная схема**:

1. При запуске приложение показывает лоадер и проверяет, есть ли новый Service Worker.
2. Если есть — применяет его и перезагружает страницу до того, как пользователь увидит интерфейс.
3. Если Service Worker «залип» (iOS) и не отвечает за 2.5 секунды, приложение смотрит на версию сборки в `localStorage`. Если она не совпадает с текущей — делает `forceReload` с параметром `?v=<timestamp>`, чтобы обойти HTTP-кэш.
4. Если и `forceReload` не помог — срабатывает предохранитель: приложение загружается в том виде, что есть, чтобы не повесить пользователя на вечном лоадере.

Версия сборки (`APP_VERSION`) генерируется автоматически в `vite.config.ts` через `__BUILD_TIME__` — это `Date.now()` в момент `npm run build`. Руками ничего менять не нужно.

### 🗜 GZIP для тяжёлых данных

Расписание, экзамены и студенты — это большие JSON-файлы, которые к тому же содержат данные сразу по всем группам. Чтобы не гонять по сети мегабайты, они отдаются **сжатыми через gzip**. Клиент распаковывает их на лету: если браузер умеет `DecompressionStream` — использует его, иначе подстраховывается `pako`. В результате на устройстве лежит уже распакованный JSON, а по сети летят сжатые байты — примерно в 5–10 раз меньше.

Реклама и лёгкие служебные ответы идут обычным JSON — их сжимать смысла нет.

### 💾 Как устроено кэширование

Клиент не перекачивает тяжёлые JSON при каждом запуске:

1. **Загрузка кэша из IndexedDB.** При старте поднимаем сохранённые данные — расписание, экзамены, студентов, рекламу.
2. **Проверка актуальности.** Лёгкий запрос к сервису сообщает, изменилось ли что-то с прошлого раза (по хэшам разделов).
3. **Перекачка только изменившегося.** Если раздел изменился, кэша нет или он пустой — качаем соответствующий файл (gzip), распаковываем и сохраняем вместе с новым хэшем. Остальные разделы не трогаем.
4. **Пустые данные не кэшируем.** Если сервер вернул пустой набор для расписания/экзаменов/студентов — это считается ошибкой, а не валидным состоянием. Показываем пользователю ошибку и кнопку «Повторить».

Реклама хэша от сервиса не имеет — для неё хэш считается локально по содержимому массива, и перекачиваем только если локальный хэш изменился.

### 🔍 Что внутри интересного

- **Виртуализация ленты недель.** Список недель семестра рендерится через `@tanstack/react-virtual` - в DOM живут только видимые элементы, даже если до конца семестра сотни недель.
- **Оптимистичный офлайн.** Приложение отдаёт кэшированные данные сразу, а обновления докачивает в фоне - пользователь никогда не ждёт.
- **Единый источник правды.** Расписание, экзамены и студенты лежат в Zustand, а IndexedDB обеспечивает персистентность.
- **Корректная отмена запросов.** Каждый сетевой вызов принимает `AbortSignal` - при переключении групп или уходе с экрана старый запрос корректно отменяется.
- **gzip на клиенте.** Тяжёлые данные приходят сжатыми и распаковываются на лету через `DecompressionStream` (с fallback на `pako`).
- **Умный логгер.** Перехватывает `console.error` и `console.warn`, дедуплицирует, сжимает и отправляет батчами в Monium. Учитывает `deviceId`, группу, тему, устройство и браузер.

### 🧪 Разработка

```bash
npm install
npm run dev          # dev-сервер Vite
npm run typecheck    # tsc --noEmit
npm run lint         # oxlint
npm run test         # vitest run
npm run build        # tsc -b && vite build
```

Тесты запускаются в `jsdom` через Vitest. Конфиг — `vitest.config.ts`, глобальные матчеры (`toBeInTheDocument` и т.п.) подключаются из `@testing-library/jest-dom/vitest` в `vitest.setup.ts`.
